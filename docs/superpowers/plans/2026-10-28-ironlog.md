# IRON LOG Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** アスリート向け筋トレ記録PWA「IRON LOG」を、記録・前回表示・カレンダー・グラフ・管理・計算ツールまで動く状態で作る。

**Architecture:** Vite + React + TypeScript の静的SPA。データは Dexie(IndexedDB) に端末内保存。計算はすべて `src/lib/` の純粋関数、DBアクセスは `src/db/repository.ts` に集約し、画面は hooks 経由でそれらを呼ぶだけにする。

**Tech Stack:** React 18, TypeScript, Vite, React Router (HashRouter), Dexie 4 + dexie-react-hooks, Recharts, vite-plugin-pwa, Vitest + @testing-library/react + @testing-library/user-event + fake-indexeddb + jsdom

**Spec:** `docs/superpowers/specs/2026-10-28-ironlog-design.md`（モックアップ: `docs/superpowers/specs/2026-10-28-ironlog-mockup.html`）

## Global Constraints

- 色トークン: 背景 `#0B0B0D`、カード `#16161A`、サブ面 `#1F1F25`、線 `#2A2A31`、文字 `#F4F4F5`、補助文字 `#8B8B94`、アクセント `#E10600`。赤は主要ボタン・完了・強度・選択中のみ
- フォント: 数字/英字見出し Oswald、日本語 Noto Sans JP（Google Fonts、フォールバックはシステムフォント）。ダーク固定
- タップ領域は最低44px。数値入力は `inputmode="decimal"`（重量・体重）/ `"numeric"`（回数・秒）
- 週は月曜始まり。日付キーはローカル時刻の `'YYYY-MM-DD'`。単位はkgのみ
- 集計対象は「ワーキングセット」= `done === true && warmup === false`。ボリュームは `weight` タイプのみ
- 入力範囲: weight 0–1000（bodyweight の加重は −200–1000）、reps 0–999、durationSec 0–36000、RPE 1–10（0.5刻み）、体重 20–300、コンディション 1–5
- 削除操作はすべて `window.confirm` で確認
- UI文言は日本語、見出しの英字ラベル（START WORKOUT 等）はモックアップに合わせる
- ルーティングは HashRouter。ルート: `/` `/calendar` `/progress` `/manage` `/workout`（進行中）`/workout/:id`（過去編集）

## Review Focus

1. 小数の重量（82.5kg、1.25kgプレート）— 浮動小数誤差で `82.49999` 表示やプレート計算の取りこぼしが起きないこと → Task 2 `formatSet`、Task 4 `platesFor` にテスト
2. 日付境界 — 日曜のワークアウトが前週ではなく当週（月曜始まり）に入る、23:59開始が当日に入る → Task 3 `startOfWeek`/`weekSummary` にテスト
3. 過去ワークアウトの編集時の「前回」— 編集中のワークアウト自身や、それより後のワークアウトを「前回」として出さない → Task 3 `previousEntry` にテスト
4. 記録中のリロード — 進行中ワークアウトがDBに残り、`startWorkout` を二重に呼んでも2件目ができない → Task 6 にテスト
5. 壊れた/別形式のJSONのインポート — 例外になり既存データが一切変わらない → Task 5 `parseBackup`、Task 6 `importAll` にテスト
