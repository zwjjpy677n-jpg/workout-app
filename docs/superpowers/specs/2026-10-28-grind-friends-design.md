# GRIND — 友達との記録共有・フィードバック・メニュー送信 設計仕様

- 作成日: 2026-10-28
- ステータス: レビュー待ち
- 前提: `2026-10-28-ironlog-design.md`（v1）と `2026-10-28-ironlog-program-design.md`（v2）を拡張する。矛盾する点は本書が優先
- 作る順番: **第1弾**（§4〜§7）→ 友達と試してもらう → **第2弾**（§8〜§9）。実装計画は弾ごとに作る

## 1. 目的

サーバーを持たないまま、友達とトレーニング記録を見せ合えるようにする。週に1回くらい、自分の記録をリンクにして LINE で送り、受け取った側は友達の記録を週ごと・種目ごと（グラフ付き）に見られる。第2弾では、見た側からコメント（フィードバック）とメニューを送り返せる。

ユーザーが決めたこと:
- 方式は「送ってもらったときだけ見られる」（サーバーなし。リンクで送る）
- リンクの中身は直近8週間の記録＋種目一覧＋メニュー＋自己ベスト
- 体重・体脂肪率は**常に**送らない
- 友達のメニューは見るだけ（自分のルーティンへのワンタップ追加はしない）
- 送るのは週1回くらいのイメージ。受け取った記録は上書きせず貯めていく
- フィードバックは「記録の日・種目へのコメント＋週のひとこと」
- 見た側がメニューを組んで送れる。受け取った側は確認してから置き換え／追加する
- メニューを置き換えても、両方の過去の記録は残す。送った・受け取ったメニューの履歴も両方に残す
- 自分のグラフは今の「グラフ」タブのままでよい（種目ごとの重量推移はすでに見られる）
- 友達に送るメニューは一から作る。種目ごとのレスト時間もメニューで決めて送る

成功基準:
- 「友達」タブから2タップ程度で、自分の記録のリンクを LINE に送れる
- iPhone のホーム画面に追加した GRIND で、LINE からコピーしたリンクを貼り付けて友達を追加できる
- 友達の記録が週ごと（日数・総ボリューム付き）に見られ、種目を押すと重量の推移グラフが出る
- 同じ友達から何度受け取っても記録が重複せず、前に受け取った分も残る
- （第2弾）コメントを送ると、相手のカレンダーのその日にコメントが出る
- （第2弾）メニューを送ると、相手は確認画面で置き換えか追加を選べ、過去の記録は変わらない

## 2. 対象外

- サーバー・アカウント・自動同期（いつでも最新が見られる方式は採らない）
- 友達の記録を自分のグラフ・カレンダー・ホームの集計・バックアップに混ぜること
- 自分のグラフ画面に友達の線を重ねる比較
- スタンプ（リアクション）
- 送った側で消した記録を、受け取った側からも消すこと（受け取った記録は残る）
- 第2弾以外の双方向機能（チャット、既読通知など）

## 3. iPhone での受け取り方（重要な制約）

iPhone では LINE のリンクを押すと LINE 内ブラウザか Safari で開き、ホーム画面に追加した GRIND では開かない。ホーム画面の GRIND と Safari は保存場所が別なので、リンクを押して保存しても、普段使っている GRIND には入らない。

そのため:
- **受け取りの基本は「貼り付け」**: LINE でリンクを長押し → コピー → GRIND の「友達」→「リンクを貼り付けて追加」
- リンクを押して開いた場合も、その場で中身を見て保存はできる（その画面に「ホーム画面の GRIND で使うには、リンクをコピーして『友達』タブに貼り付けてください」と案内を出す）
- 共有するときのメッセージにも「GRIND の『友達』タブに貼り付けてね」と一文を添える

## 4. リンクの形式（第1弾・第2弾共通）

```
https://zwjjpy677n-jpg.github.io/workout-app/#/friends/add?d=<データ>
```

- `#` より後ろはサーバーに送られないので、記録は GitHub などの外部に渡らない
- `<データ>` = 先頭1文字の種類（`r` 記録 / `f` フィードバック / `m` メニュー）＋ 版番号 `1` ＋ 本文
- 本文 = コンパクトな JSON（下記）→ `deflate-raw` で圧縮（`CompressionStream`）→ base64url
- 文字数の上限: リンク全体で **7,500 文字**（LINE の1メッセージ上限 10,000 文字と、添える文の余裕をみた値）
- 貼り付け欄はリンク全体でも `<データ>` 部分だけでも受け付ける（前後の空白・改行・添えた文は無視して `d=` を探す）
- 読めない（形式違い・壊れている・版が新しすぎる）ときは「読み込めないリンクです」と出して何も保存しない。版が新しすぎるときは「GRIND を最新にしてから貼り付けてください」

### 4.1 ID

- **自分の ID**: 初めて共有するときに作るランダムな12文字（英数字）。名前と一緒に `settings` の `{ key: 'profile', id, name }` に保存し、バックアップにも含める（復元しても同じ人として扱われるように）
- **記録・種目の短い ID**: 元の uuid の先頭8文字。1人の中で重ならなければよい。友達側では `<友達ID>:<短いID>` として保存する

### 4.2 記録データ（種類 `r`）

```ts
type SharePayload = {
  id: string;            // 送り主の ID
  n: string;             // 送り主の名前（1〜20文字）
  at: number;            // 作った時刻（分単位の UNIX 時刻）
  x: [id8: string, name: string, part: number, type: number][];   // 種目。part = BODY_PARTS の番号, type = 0 重量 / 1 自重 / 2 時間
  w: [id8: string, start: number, name: string, e: [xi: number, s: SetTuple[]][]][]; // 記録。start は分単位, xi は x の番号
  r: [name: string, weekday: number, items: [xi: number, sets: number, reps: string, main: 0 | 1][]][]; // メニュー。weekday = -1 は曜日なし
  p: [xi: number, s: SetTuple][];   // 種目ごとの自己ベスト（全期間の topSet）
};
type SetTuple = [weight: number | null, reps: number | null, sec: number | null, rpe: number | null];
```

- 記録 `w` は終了済みの記録だけ、各種目は**本番セット（完了・ウォームアップ以外）だけ**を入れる。本番セットが1つもない種目・記録は入れない
- 入れないもの: 体重・体脂肪率・コンディション・記録全体のメモ・セットのメモ・ウォームアップ・未完了のセット・目標（target）・slowed・プログラム／テスト結果
- 種目 `x` は、`w`・`r`・`p` から参照される種目だけ（アーカイブ済みでも参照されていれば入れる）
- 期間: 共有する時点から**直近8週間（56日）**。7,500 文字に収まらなければ、古い週（7日単位）から削って収める。削った場合は送る前に「直近◯週ぶんを共有します」と表示する。1週間分でも収まらなければ「記録が多すぎて共有できません」

### 4.3 フィードバック（種類 `f`、第2弾）

```ts
type FeedbackPayload = {
  id: string; n: string;   // 送り主（コメントを書いた人）
  to: string;              // 宛先（記録の持ち主）の ID
  at: number;
  c: [fid: string, wid8: string | null, week: string | null, xid8: string | null, text: string, at: number][];
  // wid8 = 記録へのコメント（xid8 があればその記録の中の種目へ）。week = 'YYYY-MM-DD'（週の月曜）なら週へのひとこと
};
```

### 4.4 メニュー（種類 `m`、第2弾）

```ts
type MenuPayload = {
  id: string; n: string; to: string; at: number;
  mid: string;             // このメニュー送信の ID（重複貼り付けの判定用）
  name: string; weekday: number;
  items: [name: string, part: number, type: number, restSec: number, sets: number, reps: string, main: 0 | 1, inc: number, note: string][];
  // restSec = このメニューでのレスト秒（10〜600）
};
```

- 種目は名前で送る（相手の GRIND の種目 ID は送り主には分からないため）

## 5. データモデル（Dexie version 3）

既存テーブルの形はほぼ変えない。変更は1点（第2弾で使う）:

- `RoutineItem.restSec?: number | null` と `EntryTarget.restSec?: number | null` を追加（メニューごとのレスト秒。無い・null なら種目のレスト秒）。記録画面のレストタイマーと表示は `target.restSec ?? exercise.restSec` を使う。移行処理は不要（無いものは null 扱い）。自分のルーティン編集にも「レスト」の欄を足す（空欄 = 種目の設定のまま）

追加するテーブル:

```ts
interface Friend {
  id: string;                  // 友達の ID
  name: string;
  receivedAt: number;          // 最後に記録を受け取った時刻
  sharedAt: number;            // 友達がリンクを作った時刻（payload.at）
  exercises: Exercise[];       // id = `${friendId}:${id8}`。restSec 0, archived false, barKg null
  routines: Routine[];         // 最新で置き換え。RoutineItem の inc は 0, note は ''
  prs: { exerciseId: string; set: WorkoutSet }[];
}

interface FriendWorkout extends Workout {   // Workout と同じ形にして、progressSeries・summarizeSets をそのまま使う
  friendId: string;            // id = `${friendId}:${wid8}`, endedAt = startedAt, note '', condition 空, routineId null
}

// 第2弾
interface FeedbackIn  { id: string; friendId: string; friendName: string; workoutId: string | null; week: string | null; exerciseId: string | null; text: string; at: number; read: boolean }
interface FeedbackOut { id: string; friendId: string; workoutId: string | null; week: string | null; exerciseId: string | null; text: string; at: number; sentAt: number | null }
interface MenuLog     { id: string; direction: 'sent' | 'received'; friendId: string; friendName: string; at: number; menu: MenuPayload; result: 'replaced' | 'added' | null }
```

ストア定義（追加分）:

```ts
friends: 'id',
friendWorkouts: 'id, friendId, startedAt',
feedbackIn: 'id, friendId, workoutId, at',     // 第2弾
feedbackOut: 'id, friendId, sentAt',           // 第2弾
menuLog: 'id, friendId, at',                   // 第2弾
```

- 第2弾のテーブルも version 3 でまとめて作る（あとから version 4 を足す手間を省く。空のテーブルは害がない）
- **バックアップ**: 友達関係のテーブルは書き出さない（受け取り直せる・自分の記録と混ぜない方針）。`profile` だけは含める（`BackupData.profile?: { id, name }`。無いバックアップも読める）

## 6. 第1弾の画面

### 6.1 タブ

下のタブを5つにする: ホーム・カレンダー・グラフ・**友達**・管理。375px 幅で文字が切れないこと。

### 6.2 「友達」タブ（`/friends`）

上から:
1. **「自分の記録を共有」ボタン**（大きめ、赤）
   - 初回は名前の入力シート（「友達に表示する名前」、1〜20文字、保存）→ 続けて共有へ
   - 共有: リンクを作り、`navigator.share({ text })` で iPhone の共有画面を出す（文: 「GRIND の記録です（〇/〇〜〇/〇・◯回分）。GRIND の『友達』タブに貼り付けてね\n<リンク>」）
   - `navigator.share` が無い・失敗したら、同じ文をクリップボードにコピーして「コピーしました。LINE に貼り付けて送ってください」
   - 共有をキャンセルしたときは何も表示しない
   - 削って収めたときは共有の前に「直近◯週ぶんを共有します」を出す
   - 名前はこの画面の下の「名前を変える」から変更できる
2. **「リンクを貼り付けて追加」ボタン**
   - シートに貼り付け欄（`textarea`）と「クリップボードから貼り付け」ボタン（`navigator.clipboard.readText` が使えるときだけ）
   - 読めたら確認画面（§6.3）へ
3. **友達の一覧**: 名前、「最後のトレーニング 10/27」、「受け取り 10/28」。押すと詳細へ。受け取った記録が無いときは「まだ友達がいません。友達に GRIND の記録を送ってもらって、ここに貼り付けてください」
4. **名前を変える**（小さめのリンク）

### 6.3 受け取りの確認（`/friends/add?d=…`）

- 「〇〇さんの記録（12回分・9/2〜10/27）」と、種目数・メニュー数
- すでにいる友達なら「前回の受け取り 10/21。新しい記録 3回分が追加されます」
- 「保存」→ 保存して友達の詳細へ。「やめる」→ 友達タブへ
- 自分の ID と同じリンク（自分の記録）なら「自分の記録です」と出して保存しない
- §3 の案内文（ホーム画面の GRIND で使うには貼り付けて、という説明）を下に小さく出す

保存のルール（`importShare`）:
- `friends` を `id` で put（名前・種目・メニュー・自己ベスト・時刻は最新で置き換え）
- `friendWorkouts` は記録ごとに `id` で put（同じ記録は最新の内容で上書き、新しいものは追加、送られてこなかった古い記録は残す）
- 1トランザクションで行う
- 前回より古いリンク（`payload.at` が保存済みの `sharedAt` より古い）を貼った場合は、記録の追加だけ行い、名前・種目・メニュー・自己ベストは置き換えない

### 6.4 友達の詳細（`/friends/:id`）

上部: 名前、「受け取り 10/28 ・ 記録 34回分」、右上の「…」に「この友達を削除」（確認あり。友達と記録をまとめて消す）。

切り替え（タブ）: **記録** / **種目** / **メニュー**

- **記録**: 週（月曜はじまり）ごとのまとまりを新しい順に。
  - 週の見出し: 「10/21〜10/27 ・ 4日 ・ 12.3t」（日数 = その週にトレーニングした日数、総ボリュームは重量種目の本番セットの合計。`volumeParts` で kg / t 表示）
  - その下に日ごとの記録: 「10/27（月） PUSH」、種目ごとに `summarizeSets` の表記（「ベンチプレス 80kg × 8 / 8 / 85kg × 5」）
  - 記録が1つも無い週は出さない
- **種目**: 友達の種目を、最後にやった日が新しい順に。名前・部位・自己ベスト（`formatSet`）・最後にやった日。押すとグラフ（§6.5）
- **メニュー**: 曜日順（曜日なしは最後）に、メニュー名・曜日・種目ごとの「3セット×5」。メイン種目には印。見るだけ

### 6.5 友達の種目グラフ（`/friends/:id/exercise/:exerciseId`）

- 自分の「グラフ」タブと同じ部品（`ProgressChart`）と指標・期間（`METRICS` / `RANGES`）を使う。データは `friendWorkouts` を `progressSeries` に渡す
- 重量種目は推定1RM・最大重量・ボリューム、自重は最大加重・総回数、時間は最長・合計時間
- 下に自己ベストと、直近の記録を5回分（日付と `summarizeSets`）

## 7. 第1弾のコード構成

```
src/lib/share/
  codec.ts        // encode(kind, json) / decode(text): 圧縮・base64url・種類と版の判定、d= の取り出し
  sharePayload.ts // buildSharePayload(db データ, now) → SharePayload（8週間・本番セットのみ・7,500文字に収まるまで週を削る）
  importShare.ts  // SharePayload → Friend / FriendWorkout への変換（純粋関数）
src/db/friends.ts // getProfile / saveProfile / listFriends / getFriend / listFriendWorkouts / saveImportedShare / deleteFriend
src/features/friends/
  FriendsPage.tsx, ShareButton.tsx, NameSheet.tsx, PasteSheet.tsx,
  ImportPage.tsx, FriendPage.tsx, FriendWeeks.tsx, FriendExercises.tsx, FriendMenus.tsx,
  FriendExercisePage.tsx, friends.module.css
```

- `useLiveQuery` で一覧・詳細を更新（既存の `useData.ts` と同じやり方）
- 圧縮は `CompressionStream('deflate-raw')` / `DecompressionStream`（iOS 16.4 以降・Chrome・Node 18 以降で使える）。無い環境では「この端末では共有を使えません」と出す
- 友達関係の文字列はすべて画面に出す前にそのまま文字として描画する（HTML として解釈しない。React の通常の描画で満たす）
- 受け取ったデータは値の範囲を確認してから保存する（名前 1〜40 文字、種目名 1〜40 文字、重量 −200〜1000、回数 0〜999、秒 0〜36000、RPE 1〜10、配列の長さ上限: 種目 300・記録 500・メニュー 30）。範囲外が1つでもあれば「読み込めないリンクです」

## 8. 第2弾: フィードバック

### 8.1 書く（見る側）

- 友達の詳細「記録」で、日ごとの記録・その中の種目・週の見出しに「💬」ボタン
- 押すとシートで1〜300文字のコメントを書く → `feedbackOut` に下書きとして保存（`sentAt: null`）。書いたコメントはその場所の下に「あなた: …（未送信）」と出る。下書きは編集・削除できる
- 友達の詳細上部に「フィードバックを送る（3件）」ボタン（未送信が1件以上のとき）→ 種類 `f` のリンクを作って共有（§6.2 と同じ共有の流れ）。共有を終えたら（キャンセル以外）`sentAt` を入れて「送信済み」にする。送信済みは消さずに表示し続ける
- リンクが長すぎるときは、古いコメントから次回に回し「◯件だけ送ります。残りは次に送ってください」

### 8.2 受け取る（記録した側）

- 「リンクを貼り付けて追加」で受け付ける（種類で見分ける）。確認画面「〇〇さんからのフィードバック（3件）」→「保存」
- `to` が自分の ID でなければ「あなた宛てではないフィードバックです」で保存しない。まだ ID が無い（一度も共有していない）人も同じ
- `feedbackIn` に `fid` で put（同じリンクを2回貼っても重複しない）
- `wid8` / `xid8` は自分の記録・種目の uuid の先頭8文字なので、前方一致で自分の記録・種目を探して `workoutId` / `exerciseId` に完全な ID を入れる。見つからなければ null のまま保存する
- 表示場所:
  - カレンダーの日の詳細（`DayDetail`）: 記録の下にその記録へのコメント、種目へのコメントはその種目の下に「〇〇さん: …」
  - 「友達」タブの「届いたフィードバック」: 新しい順。未読に印。押すとカレンダーのその日へ移り、既読にする。週へのひとことはその週の月曜へ
  - コメント先の記録が消えていても、「届いたフィードバック」には残る（日付は `at` で表示）

## 9. 第2弾: メニューを組んで送る・受け取る

### 9.1 組んで送る（見る側）

- 友達の詳細「メニュー」に「メニューを組んで送る」ボタン → 空のメニューから一から作る
- 編集画面は既存の `RoutineForm` と同じ形（名前・曜日・種目ごとのセット数・目標・**レスト**・メイン・上げ幅・メモ）。レストは −/＋ で15秒刻み、初期値は90秒。種目は一覧から選ぶか、名前を入力して新しく作る
- 「送る」→ 種類 `m` のリンクを共有。送ったら `menuLog` に `direction: 'sent'` で保存
- 友達の詳細「メニュー」の下に「送ったメニュー」の履歴（日時・メニュー名・種目数）。押すと内容を見られる

### 9.2 受け取る（記録した側）

- 貼り付け → 確認画面: 「〇〇さんからのメニュー『PUSH（月）』」と種目の一覧
  - 自分の GRIND に**名前が同じ種目**があればそれを使う。無い種目は「新しく追加される種目」として一覧に出す
  - 同じ名前のメニューがあれば「置き換える」「別のメニューとして追加」を選ぶ。無ければ「追加する」だけ
  - 「やめる」もある
- レストはメニューの各種目（`RoutineItem.restSec`）に入れる。既存の種目のレスト設定は変えない（ほかのメニューに影響させない）
- 保存: 無い種目を作成（レストは送られてきた値で作る） → メニューを置き換え（同じ ID のまま `items`・曜日を更新）または新規作成 → `menuLog` に `direction: 'received'`、`result` 付きで保存。1トランザクション
- 同じ `mid` をもう一度貼ったら「このメニューは受け取り済みです」
- `to` の確認は §8.2 と同じ
- 管理 → ルーティンの下に「受け取ったメニュー」の履歴（日時・誰から・メニュー名・置き換え／追加）

### 9.3 記録が残ることの保証

- 過去の記録は `Workout.entries[].target` にその日の目標を持っているので、メニューを置き換えても記録・カレンダー・グラフは変わらない（既存の仕組み。テストで確認する）
- メニューの置き換えでは `Routine.id` を変えないので、進行中の記録の `routineId` も切れない
- 見る側の友達の記録（`friendWorkouts`）はメニュー送信で一切変えない

## 10. エラー処理

| 状況 | 表示 | 保存 |
|---|---|---|
| リンクが壊れている・GRIND のものでない | 読み込めないリンクです | しない |
| 版が新しすぎる | GRIND を最新にしてから貼り付けてください | しない |
| 自分の記録のリンク | 自分の記録です | しない |
| 宛先が自分でない（f / m） | あなた宛てではない〇〇です | しない |
| 受け取り済みのメニュー | このメニューは受け取り済みです | しない |
| 圧縮が使えない端末 | この端末では共有を使えません | — |
| 記録が多すぎる | 記録が多すぎて共有できません | — |
| 保存（IndexedDB）の失敗 | 保存できませんでした。もう一度お試しください | 途中まで保存しない（トランザクション） |

## 11. テスト

- `codec`: 往復で同じ内容／種類と版の判定／リンク全体・`d=` だけ・前後に文がある貼り付けの取り出し／壊れた入力の拒否
- `sharePayload`: 8週間で切る／本番セットだけ／送らない項目が入っていない（体重・メモ・コンディション等）／参照される種目だけ／7,500 文字を超えると古い週から削る／1週間でも超えるとエラー
- `importShare`: 値の範囲確認／ID の付け方／記録を貯める（重複しない・古い記録が残る）／古いリンクで名前等を戻さない
- 画面: 初回の名前入力→共有／`navigator.share` が無いときのコピー／貼り付け→確認→保存→詳細／自分のリンクを拒否／週ごとの見出し（日数・総ボリューム）／種目グラフが出る／友達の削除／5タブが 375px で収まる
- 第2弾: コメントの下書き→送信済み／宛先違いの拒否／重複貼り付け／カレンダーに出る／未読→既読、メニューの名前で種目を合わせる・無い種目の作成／置き換えでも過去の記録・カレンダー・グラフが変わらない／受け取り済みの拒否／履歴が両方に残る
- 移行: version 2 の DB（記録あり）を開いて version 3 になり、既存データが変わらない。`profile` 無しのバックアップも読める
