# IRON LOG — 8週間プログラム・おすすめ重量・記録画面リニューアル 設計仕様

- 作成日: 2026-10-28
- ステータス: レビュー待ち
- 前提: `2026-10-28-ironlog-design.md`（v1）を拡張する。v1 の記述と矛盾する点は本書が優先
- 参考: ユーザー提示のトレーニング記録アーティファクト（おすすめ重量・8週間ブロック・曜日メニュー・開閉式の記録画面）

## 1. 目的

「今日は何を、何kgで、何セットやるか」をアプリが提示し、アスリートは押すだけで記録できるようにする。見た目は v1 のダーク×レッドを維持する。

成功基準:
- ホームを開くと今日のメニューと「何週目か」が分かり、ワンタップで始められる
- 各種目を開くと、前回の結果から決めた「今回のおすすめ重量」と理由、プレート図が出る
- セットは −/＋ で数値を合わせ、完了を押すだけ。「この種目を完了して次へ」で次の種目が開く
- 8週間のうち4・8週目は回復週（セット数半分）、8週目に5RMと体重のテストで伸びを比べられる

## 2. 対象外

- 配色・書体の変更（ダーク×レッドのまま）
- 仲間との共有、睡眠記録、週ボリュームの棒グラフ
- プログラム期間・回復週の変更（8週固定、回復週4・8週目固定）

## 3. データモデル（Dexie version 2）

```ts
interface Exercise {               // 追加: barKg
  ...v1;
  barKg: number | null;            // この種目のバー重量。null = 設定のバー重量。プレート図はこの値が非nullの種目だけに出す
}

interface RoutineItem {
  exerciseId: string;
  sets: number;                    // 目標セット数 1–20
  reps: string;                    // 目標の表記（"5", "左右8", "8〜10", "6〜8本", "左右30秒"）
  main: boolean;                   // メイン種目
  inc: number;                     // 重量の上げ幅 kg（0.5–20）
  note: string;
}

interface Routine {                // 変更: exerciseIds → items、weekday 追加
  id: string;
  name: string;
  weekday: number | null;          // 0=日 … 6=土。null = 曜日なし
  items: RoutineItem[];
  createdAt: number;
}

interface EntryTarget {            // ルーティンから始めたときの目標のスナップショット
  sets: number; reps: string; main: boolean; inc: number; note: string;
}

interface WorkoutEntry {           // 追加: target, slowed
  exerciseId: string;
  sets: WorkoutSet[];
  target?: EntryTarget;            // 自由に追加した種目は undefined
  slowed?: boolean;                // メイン種目「最後の回でスピードが落ちた」
}

interface Workout {                // 追加: routineId
  ...v1;
  routineId: string | null;
}

interface TestResult {
  date: string;                    // 'YYYY-MM-DD'
  bodyweight: number | null;
  lifts: Record<string, number>;   // exerciseId → 5RM の重量 kg
}

interface Program {
  startDate: string;               // 'YYYY-MM-DD'。開始日が1週目の初日で、7日ごとに次の週
  tests: { start: TestResult | null; end: TestResult | null };
}
```

- `settings` テーブルにキー `'program'` で Program を1件保存（未開始なら行なし）
- 移行（version 2 upgrade）:
  - routines: `exerciseIds` → `items`（各 `{ sets: 3, reps: '10', main: false, inc: 2.5, note: '' }`）、`weekday: null`
  - exercises: `barKg: null`。ただしシード名「ベンチプレス」「スクワット」「デッドリフト」は 20
  - workouts: `routineId: null`
- 目標回数の数値 `targetNumber(reps)` = 表記中の最初の数値（"8〜10"→8、"左右30秒"→30、"6〜8本"→6、数字なし→null）

## 4. 参考メニュー（初期データ）

- `ensureMenuSeeded()`: 設定キー `'menuSeeded'` が無く、かつルーティンが0件なら投入し、`'menuSeeded'` を記録する（新規インストールと、ルーティン未作成の既存ユーザー）

## 5. プログラム（8週固定）

- `weekOf(startDate, date)` = `floor((date − startDate) / 7日) + 1`（開始日前は 0 以下）
- 回復週: 4・8週目
- 状態の表示:
  - 1–8週: 「N週目 / 8」、回復週は「回復週：重さはそのまま、セット数を半分に」
  - 0以下: 「開始前」
  - 9以上: 「8週間完了」「グラフ › 8週間テストで結果を入力しましょう」
- 開始・終了は 管理 › プログラム から。開始中に「次の8週間を始める」「プログラムを終了」を選べる（どちらも確認あり。テスト結果はリセット）

## 6. おすすめ（純粋関数 `suggest`）

入力: `target: EntryTarget`, `type: ExerciseType`, `prev: { sets: WorkoutSet[]; slowed: boolean } | null`（前回その種目を行ったワークアウトのエントリー。v1 の `previousEntry`）, `deload: boolean`。

出力: `{ sets: number; weight: number | null; reps: number | null; durationSec: number | null; reason: string }`

- `sets` = 回復週なら `max(1, ceil(target.sets / 2))`、それ以外 `target.sets`
- `r` = `targetNumber(target.reps)`。`reps` = type が time なら null、それ以外 r。`durationSec` = type が time なら r、それ以外 null
- `lw` = 前回のワーキングセットの最大重量（無ければ 0）
- type が weight 以外:
  - weight = bodyweight で lw ≠ 0 なら lw、それ以外 null
  - reason = 回復週「回復週：セット数を減らして軽めに」／それ以外「前回より質を上げることを意識」
- type が weight:
  - 前回なし or lw = 0 → weight null、「初回：フォームが崩れず、目標回数をきれいにこなせる重さで」
  - 回復週 → lw、「回復週：重さはそのまま、セット数を半分に」
  - `hit` = r が null、または前回の重量 lw のワーキングセットすべてで reps ≥ r
  - メイン: slowed → lw「前回スピードが落ちたので、同じ重さでやり直し」／!hit → lw「前回は目標回数に届かなかったので、同じ重さ」／それ以外 lw+inc「前回はスピードを保てたので+{inc}kg」
  - メイン以外: hit → lw+inc「全セット目標回数に届いたので+{inc}kg」／それ以外 lw「全セットで目標回数に届くまで同じ重さ」
  - 重量は小数第2位で丸める

## 7. 画面

### 7.1 ホーム
- プログラム中: 最上部に週ヘッダー（大きな「N週目 / 8」、8本のバー＝過去週は白・今週は赤・回復週は斜線、状態ラベル）
- 「今日のトレーニング」カード（今日の曜日のルーティンがある場合）
  - ピル「N週目 / 8 ・ 回復週」（プログラム中のみ）、「進捗 完了種目数 / 種目数」、ルーティン名（大）、「N種目 ・ Nセット」、進捗バー
  - ボタン: 今日このルーティンの進行中ワークアウトあり →「続きを記録する」／今日このルーティンの完了済みあり →「記録を見直す」（カレンダーの今日へ）／それ以外 →「トレーニングを始める」
  - 別のワークアウトが進行中のときは「進行中のワークアウトを再開」（v1 の RESUME）を優先して表示
- 今日の曜日のルーティンがない場合: 「今日は休み」＋「次は◯曜 ルーティン名」＋「自由に記録する」ボタン
- 「完了種目」= ワーキングセットが1つ以上あり、未完了のワーキングセットがない種目（ウォームアップは数えない）
- v1 の体重カード、今週の集計、ルーティン一覧、部位別セット数、最近の記録はこの下に残す。START WORKOUT は「自由に記録する」に名前を変えて今日のカードの下へ

### 7.2 ルーティンから開始
- `startRoutineWorkout(routineId, now)`: 進行中があればそれを返す。無ければ各 item について `previousEntry` と `suggest`（回復週はプログラム中かつ当日の週が4・8のとき）から entry を作る
  - `target` = item のスナップショット
  - セット数 = suggest.sets、各セット weight/reps/durationSec = suggest の値（実値として入れる。done=false）
  - アーカイブ済み・存在しない種目の item は飛ばす
- Workout.name = ルーティン名、routineId を保存

### 7.3 記録画面（開閉式）
- 種目は番号付きの行。行ヘッダー: 番号バッジ（完了種目は ✓）、種目名、メインなら「メイン」タグ、PR バッジ、2行目「3セット×5 ・ レスト 3:00」（target 無しは「レスト 3:00」）と「前回 M/D ・ 80kg × 8」
- タップで開閉。開いた行は1つ。初期は「最初の未完了の種目」を開く
- 開いた中身:
  - おすすめブロック（target がある種目のみ）: 見出し「今回のおすすめ」、大きな重量「85kg ×5」（weight null なら「今回の目標」と回数表記）、プレート図（重量 ≥ バー、かつ exercise.barKg 非null）、理由
  - 小さな情報行: 前回（日付・セット要約）、目標セット数、前回の推定1RM（weight）、レスト、前回スピードが落ちた（該当時）
  - target.note があれば表示
  - セットカード: 「1 セット目」（タップでウォームアップ「W」切替）、前回の同番号セット、メモ、削除×（2セット以上）、完了ボタン（完了で赤）。入力は −/＋ 付きステッパー（重量: 上げ幅 or 2.5 刻み、回数: 1、秒: 5）と小さな RPE 欄
  - ボタン: 「＋ セット追加」、メインなら「最後の回でスピードが落ちた」トグル、「この種目を完了して次へ」（入力のあるセットをすべて完了にし、次の未完了種目を開く）／完了済みなら「完了を取り消す」
- 完了ボタンの規則は v1 の completeSet（必須値が無ければ完了にしない）。完了でレストタイマー開始
- PR・ワークアウトメモ・コンディション・%1RM・プレート計算・種目追加・終了は v1 のまま

### 7.4 プレート図
- 色: 25kg #D7263D、20kg #1F5BC6、15kg #E3B22A、10kg #2E8F56、5kg #F7F8FA、2.5kg #5A6470、1.25kg #AEB6C0。高さは重いほど大きい
- バーは片側のみ描き、横に「片側 20 + 10 + 2.5 ・ バー20kg」、端数があれば「（端数 1kg）」
- v1 のプレート計算シートの図もこれに置き換える

### 7.5 管理
- 種目編集: 「バー重量（kg・空欄なら設定値）」を追加
- ルーティン編集: 曜日（なし/月〜日）、各種目の セット数・回数表記・メイン・上げ幅・メモ、並べ替え・削除。「参考メニューを読み込む」ボタン（一覧の下）
- 新タブ「プログラム」: 未開始なら説明と開始日入力・「この日から始める」。開始中は開始日・現在の週・状態、「次の8週間を始める」「プログラムを終了」

### 7.6 グラフ画面
- 先頭に「8週間テスト」カード（プログラム開始済みのときのみ）
  - 行: メイン種目（いずれかのルーティンで main の種目）＋体重。列: 開始時 / 8週目 / 伸び（▲▼、kg）
  - 「開始時を入力」「8週目を入力」ボタン → シートで各5RM と体重を入力（NumberInput）、日付は今日

## 8. バックアップ

- `version: 2`。`program: Program | null` を追加。routines は新形式
- `parseBackup` は version 1 も受け付け、3章の移行と同じ変換をして返す

## 9. テスト方針

- 純粋関数（targetNumber, weekOf, isDeload, suggest, buildRoutineEntries, entryComplete, plateLayout）は網羅的にユニットテスト
- Dexie 移行: version 1 のデータを入れて version 2 で開き、routines/exercises/workouts が変換されること
- ensureMenuSeeded の冪等性・既存種目の再利用、参考メニュー読み込みの追加と名前重複
- 画面: ホームの今日カード（曜日一致・休み・続き・見直し）、記録画面の開閉・おすすめ表示・ステッパー・完了して次へ・スピード低下、テストカードの入力と伸び
- 既存の 116 テストは新UIに合わせて更新し、振る舞いの保証（前回表示・ウォームアップ・PR・レスト・終了処理）は維持する
