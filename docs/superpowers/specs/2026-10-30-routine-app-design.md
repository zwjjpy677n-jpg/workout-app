# ルーティン — 毎日の習慣とその日のやること 設計仕様

- 作成日: 2026-10-30
- ステータス: レビュー待ち
- 置き場所: GRIND と同じリポジトリの `routine/`（別アプリ）。GRIND 側のファイルは変えない

## 1. 目的

アスリートが自分の生活を毎日チェックするための、自分専用のアプリ。朝起きてからのルーティン（体重測定、水を飲む、練習後のストレッチ、睡眠時間など）と、その日だけのやることを1画面で片づける。続いた日数と達成率を見て、習慣が崩れていないかを確かめられるようにする。

ユーザーが決めたこと:
- 使うのは自分だけ。日々のルーティン＋その日のやることに、アスリートの生活習慣管理を合わせた使い方
- GRIND の中ではなく、同じリポジトリの別アプリとして作る
- 作り方は「同じ `package.json` のまま `routine/` を足し、共通部品は `src/components` から読む」（案1）
- ルーティンは次の4つを全部入れる
  - 時間帯で分ける（朝／練習前／練習後／夜）
  - 曜日で変える（練習日とオフの日で中身が違う）
  - チェックだけでなく数値も残せる（水 1500ml、睡眠 7.5時間）
  - 連続日数と達成率を見られる
- その日のやることは、その日だけのチェックリスト。できなかったものは翌日に持ち越せる

成功基準:
- 開いてすぐの「今日」画面で、今日やるルーティンとやることが全部見え、1タップでチェックできる
- 数値の項目は、目標に届いた時点で自動でできたことになる
- 昨日できなかったやることを、ボタン1つで今日に移せる
- 記録タブで、日ごとの達成率がカレンダーの色でわかり、連続日数と週・月の達成率が出る
- `npm test`、型チェック、GRIND とルーティン両方のビルドが通る

## 2. 作り方の全体

| ファイル・フォルダ | 役割 |
|---|---|
| `routine/index.html` | 入口の HTML |
| `vite.routine.config.ts` | ルーティン用のビルド設定。`root: 'routine'`、出力は `dist-routine/`。PWA の名前・アイコン・色は GRIND と別 |
| `routine/src/main.tsx`, `App.tsx` | 起動とタブの切り替え（react-router-dom） |
| `routine/src/db/` | Dexie のデータベース定義と読み書きの関数 |
| `routine/src/lib/` | 計算だけをする関数（画面やデータベースに依存しない） |
| `routine/src/features/today`, `history`, `routines` | 3つのタブの画面 |
| `routine/src/styles/` | アクセント色だけを上書きするトークン |

`package.json` に `dev:routine`、`build:routine`、`preview:routine` を足す。テストは今の `vitest` の設定のまま `routine/` 以下も拾う（拾わなければ `include` に足す）。型チェックは `tsconfig.json` の `include` に `routine` を足して `npm run lint` で一緒に見る。

共通部品は `src/components` の Button、Card、Sheet、Stepper、NumberInput、TabBar などを相対パスで読む。`src/styles/tokens.css` と `global.css` も読み、アクセント色の変数だけルーティン側で上書きする。GRIND 側の部品に手を入れる必要が出たら、その時点で相談する。

## 3. データ

IndexedDB に Dexie で保存する。データベース名は `routine`（GRIND の DB とは別）。

### 3.1 ルーティン項目 `items`

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | string | UUID |
| `name` | string | 例: 水を飲む |
| `slot` | `'morning' \| 'pre' \| 'post' \| 'night'` | 時間帯（朝／練習前／練習後／夜） |
| `days` | number[] | やる曜日（0=日〜6=土）。毎日なら7つ全部 |
| `kind` | `'check' \| 'number'` | チェックだけか、数値か |
| `target` | number? | 数値の目標（`kind === 'number'` のときだけ） |
| `unit` | string? | 単位（ml、時間、kg など） |
| `step` | number? | −/＋で増減する幅（例: 水は 250） |
| `order` | number | 時間帯の中での並び順 |
| `active` | boolean | false なら休止中。今日の画面にも統計の分母にも入れない |
| `createdAt` | number | 作った時刻（ms） |
| `deletedAt` | number? | 消した時刻。過去の記録を残すため、行は消さない |

### 3.2 ルーティンの記録 `logs`

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | string | `${date}:${itemId}`。1日1項目につき1件 |
| `date` | string | `YYYY-MM-DD`（端末の日付） |
| `itemId` | string | 項目の ID |
| `done` | boolean | できたか |
| `value` | number? | 数値の項目の値 |

数値の項目は `value >= target` のとき `done = true` にする。値を下げて目標を割ったら `false` に戻す。

### 3.3 その日のやること `todos`

| 項目 | 型 | 説明 |
|---|---|---|
| `id` | string | UUID |
| `date` | string | やる日 |
| `text` | string | 内容 |
| `done` | boolean | できたか |
| `order` | number | 並び順 |
| `carriedFrom` | string? | 持ち越し元の日付（表示用） |

### 3.4 計算のルール（`routine/src/lib/`）

- その日にやる項目: `days` にその日の曜日が入っていて、`createdAt` がその日の終わりより前で、`deletedAt` がないかその日より後のもの。そのうえで
  - 今日: `active` のものだけ
  - 過去の日: `active` のもの＋休止中でもその日の `logs` があるもの（休止した時刻は持たないので、記録が残っている日だけ数える）
- 達成率: その日のできた項目数 ÷ その日にやる項目数。やる項目が0件の日は「対象外」として、カレンダーは色なし、連続日数も途切れない（数えもしない）
- 連続日数: 今日から過去にさかのぼり、全部できた日が何日続いたか。今日がまだ全部できていないときは昨日から数える（朝に開いて0日と出ないように）
- 持ち越し: 今日より前の日で、できていないやることを一覧にする。「持ち越す」を押すと、そのやることの `date` を今日に変え、`carriedFrom` に元の日付を入れる（複製はしない）
- やることは達成率に入れない。達成率と連続日数はルーティンだけで数える

## 4. 画面

下のタブは「今日」「記録」「ルーティン」の3つ。

### 4.1 今日（最初に出る画面）

- 上に日付、今日の達成率（7/10・70%）、🔥連続日数
- 時間帯ごとにルーティンを並べる。その時間帯に今日やる項目がなければ、見出しごと出さない
  - チェックの項目: 行をタップで切り替え
  - 数値の項目: −/＋（`step` ずつ）と直接入力。`1000 / 1500 ml` のように出し、目標に届いたらチェックが付く
- 「今日のやること」: 入力欄から追加、タップでできた、メニューから編集・削除・上下の並べ替え
- 今日より前にできていないやることがあれば「未完了が3件あります」と出し、押すと一覧のシートが開いて、全部または選んだものを持ち越せる

### 4.2 記録

- 月のカレンダー。日ごとの達成率で3段階の色（〜49%／50〜99%／100%）。色の付け方は GRIND のカレンダーに合わせる
- 日付をタップするとシートでその日の中身が出て、チェックや数値を後から直せる
- 今週・今月の達成率、今の連続日数、最長の連続日数
- 項目ごとの達成率（直近30日）
- 数値の項目は、選んだ項目の値の推移グラフ（recharts、直近30日）

### 4.3 ルーティン

- 項目の一覧を時間帯ごとに出す。休止中のものは薄く出す
- 追加・編集はシートで開く。名前、時間帯、曜日（毎日／曜日を選ぶ）、種類（チェック／数値）、数値なら目標・単位・増減の幅
- 並べ替えは上下ボタン。休止と削除は編集シートの中に置く（削除は確認あり）
- 最初に開いたとき、参考の項目を入れておく

| 名前 | 時間帯 | 種類 |
|---|---|---|
| 体重をはかる | 朝 | チェック |
| 水を飲む | 朝 | 数値 1500ml（250ずつ） |
| アップ・動的ストレッチ | 練習前 | チェック |
| プロテインをとる | 練習後 | チェック |
| 静的ストレッチ | 夜 | チェック |
| 睡眠 | 夜 | 数値 7.5時間（0.5ずつ） |

### 4.4 見た目

GRIND の暗い画面とフォント（Noto Sans JP、数字は Oswald）をそのまま使い、アクセント色だけ緑系に変える。PWA の名前は「ルーティン」、テーマ色は GRIND と同じ `#0B0B0D`。アイコンは仮のものを `routine/public/` に置く。

## 5. うまくいかないとき

- IndexedDB が開けない（プライベートモードなど）ときは、GRIND の `checkStorage` を読んで、起動時に「この端末では保存できません」と出す
- 項目を消しても `logs` は残す。統計の項目ごとの一覧では「（削除済み）」を付けて出す
- 日付は端末の時刻で決める。日付をまたいで開きっぱなしのときは、画面に戻った（`visibilitychange`）ときに今日を計算し直す

## 6. テスト

- `routine/src/lib/` の計算は、テストを先に書いてから作る。確かめること
  - 曜日の判定（毎日／特定の曜日）
  - 月の変わり目と年の変わり目の連続日数
  - やる項目が0件の日の扱い
  - 休止・削除した項目の扱い
  - 今日が未完了のときの連続日数の数え方
  - 数値の目標に届いた・割ったときの `done`
  - 持ち越し
- `routine/src/db/` の読み書きは fake-indexeddb で確かめる
- 画面は Testing Library で、チェック、数値の入力、やることの追加・持ち越し、項目の追加を確かめる
- 最後に `npm test`、`npm run lint`、`npm run build`、`npm run build:routine` が全部通ることを確かめる
