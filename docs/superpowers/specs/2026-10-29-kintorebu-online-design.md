# キントレ部 — オンライン共有（自動共有・グループ） 設計仕様

- 作成日: 2026-10-29
- ステータス: レビュー待ち
- 前提: 既存のキントレ部（React 18 + TypeScript + Vite PWA、Dexie、HashRouter、Capacitor 8 の iPhone アプリ）。友達のリンク共有（`2026-10-28-grind-friends-design.md`）と見た目の設定はそのまま

## 1. 目的

トレーニングを終えたら、記録がサーバー経由で友達とグループのメンバーに**自動で**届き、アプリの中でまとめて見られるようにする。グループでは、メンバーの記録にリアクションとコメントを付けられる。

ユーザーが決めたこと:
- 使う人: 自分と身近な仲間（数人〜20 人程度）。アプリは App Store で公開する
- 自動共有の中身: その日の記録すべて（メニュー名・種目・重さ・回数・秒数・RPE）＋**ワークアウト時間**。トレーニングを終えると、友達とグループの画面にその日の内容が自動で出る
- 予定のメニュー（ルーティン）は自動では送らない。送りたいときに送る。オンラインの友達には LINE を使わずアプリの中で直接届く
- グループ: 記録の一覧＋リアクション＋コメント。チャットは作らない
- 通知: 最初は無し。アプリ内の未読の印だけ（スマホへの通知は後で足す）
- 今のリンク共有と、リンクで追加した友達は残す
- ログイン: メールアドレス＋6 桁の確認コード（パスワード無し）
- サーバー: Supabase（無料プラン）

成功基準:
- A と B が友達になり、A が「終了」を押すと、B が友達タブを開いたときに A の記録（ワークアウト時間を含む）が表示される
- A がオンラインの友達 B にメニューを送ると（組んで送る・自分のメニューを選んで送る）、B のアプリの中に届き、今のメニュー一覧・版の履歴に入る
- グループのメンバーの記録が新しい順に並び、リアクションとコメントが付けられ、ほかのメンバーにも見える
- 電波が無いときに終えた記録は、つながったときに自動で送られる
- 友達でもグループのメンバーでもない人の記録・コメントは、サーバーから取れない（サーバー側の決まりで守る）
- ブロックした相手の記録・コメントはお互いに見えない
- アプリからアカウントを削除でき、サーバー上のその人のデータが消える
- サーバーにつながらなくても、記録をつける機能はいつもどおり動く

## 2. 対象外

- スマホへの通知（プッシュ通知）
- チャット、写真、プロフィール画像
- 見せる相手を記録ごと・人ごとに選ぶこと（外したい相手はブロック）
- 知らない人の検索・友達申請（つながるのは招待リンクだけ）
- 体重・体脂肪率・メモ・コンディション・ウォームアップの共有（今と同じく共有しない）
- 予定のメニュー（ルーティン）の自動共有（送るのは本人が送ったときだけ）
- グループへのメニュー送信（メニューは友達 1 人ずつに送る）

## 3. 共有する記録

自動共有するのは、終わった（`endedAt` がある）トレーニング 1 回分:
- id、メニュー名、開始時刻 `startedAt`、終了時刻 `endedAt`（ワークアウト時間 = 終了 − 開始）
- 種目ごとに: 種目名・部位・種類（重量／自重／時間）、ウォームアップ以外の完了したセットの重さ・回数・秒数・RPE
- 上限は今のリンク共有の `LIMIT` に合わせる（名前の長さ、種目数、セット数）

表示の呼び方: トレーニング全体の長さは「ワークアウト時間」（例「62分」）、セットの秒数は「秒数」。

## 4. サーバー（Supabase）

### 4.1 表

`supabase/schema.sql` に、表・関数・「誰が見られるか」の決まり（RLS）をまとめて書く。ユーザーが Supabase の管理画面（SQL Editor）に貼り付けて実行する。

| 表 | 中身 |
|---|---|
| profiles | id（= ログインのユーザー ID）、name（1〜20 字）、created_at |
| friendships | user_a, user_b（a < b で 1 行）、created_at |
| groups | id, name（1〜30 字）, owner, created_at |
| group_members | group_id, user_id, joined_at |
| invites | code（推測できない 22 字）、kind（friend / group）、owner、group_id、expires_at（7 日後）、used_by |
| shared_workouts | id（端末の記録 id）、user_id、started_at、ended_at、name、body（jsonb: §3 の種目とセット）、updated_at、deleted（bool） |
| reactions | workout_id, user_id, emoji（💪 🔥 👏 のどれか）、created_at。1 人 1 記録 1 種類 1 回 |
| comments | id, workout_id, user_id, body（1〜200 字）、created_at、deleted |
| menu_messages | id, sender, recipient, kind（built = 組んで送る / mine = 自分のメニュー）、body（jsonb: 今の menuPayload / sharePayload のメニュー部分と同じ中身）、created_at |
| blocks | blocker, blocked |
| reports | id, reporter, target_kind（workout / comment / user）、target_id、reason（0〜200 字）、created_at |

### 4.2 誰が見られるか（RLS）

- 「つながっている」= 友達である、または同じグループのメンバーである。ただし、どちらかがブロックしていれば、つながっていないものとして扱う
- shared_workouts: 本人はすべて読み書きできる。つながっている人は読むだけ
- reactions / comments: その記録を読める人は、読めて、自分の分を足せる。消せるのは自分の分だけ（コメントは `deleted` にする）
- profiles: 本人と、つながっている人が読める。書けるのは本人だけ
- groups / group_members: メンバーだけが読める。名前を変えられるのは owner だけ。抜けるのは本人
- invites: 作るのは本人。使うのは関数 `accept_invite(code)` だけを通す。期限切れ・使用済み（友達の招待）なら失敗させる。グループの招待は期限内なら何人でも使える
- menu_messages: 送れるのは友達（ブロックしていない）にだけ。読めるのは送った人と受け取った人だけ
- blocks / reports: 本人の分だけ書ける。reports は誰も読めない（管理画面で開発者だけが見る）
- 関数 `delete_account()`: 本人のデータ（profiles・shared_workouts・reactions・comments・friendships・group_members・invites・blocks）を消し、ログインのユーザーも消す。owner だったグループは、ほかのメンバーがいれば一番古いメンバーに引き継ぎ、いなければ消す

### 4.3 ログイン

- Supabase Auth のメール OTP（6 桁コード）。メール本文のテンプレートは「キントレ部の確認コード: {{ .Token }}」にする（手順書で設定）
- アプリに書くもの: Supabase の URL と anon key（公開してよい鍵）。`src/lib/online/config.ts` にまとめる。空ならオンライン機能を出さない

## 5. アプリ側

### 5.1 構成

- `src/lib/online/` にオンライン機能をまとめる。画面はここ経由でしかサーバーに触れない
  - `client.ts`: Supabase クライアント（テストでは偽物に差し替える）
  - `auth.ts`: コードを送る、コードで入る、ログアウト、今のユーザー
  - `outbox.ts`: 送る予定の箱（Dexie の新しい表 `outbox`）。追加・送信・送り直し
  - `pull.ts`: 前回より新しい記録・リアクション・コメント・メンバーを取ってきて Dexie にしまう
  - `menus.ts`: メニューを送る・届いたメニューを取ってくる
  - `invites.ts`, `groups.ts`, `social.ts`（リアクション・コメント・通報・ブロック）, `account.ts`（アカウント削除）
- Dexie v4 で表を足す: `outbox`、`onlineGroups`、`groupMembers`、`reactions`、`comments`、`blocks`、`sync`（前回取ってきた時刻など）。バックアップには入れない
- オンラインの友達は、今の `friends` / `friendWorkouts` に入れる。`Friend` に `online?: { userId: string }` を足す。これで今の友達の画面（週ごと・種目・グラフ）がそのまま使える

### 5.2 送る

- 記録を「終了」したとき、終わった記録を直したとき、消したときに、`outbox` に 1 件足す（同じ記録の古い分は上書き）
- ログインしていて自動共有がオンなら、すぐ送る。失敗した分は残し、アプリを開いたとき・ネットに戻ったとき・友達タブを開いたときに送り直す
- 初めてログインしたとき、「直近 8 週間の記録を共有しますか？」と聞く。はいなら直近 8 週間の終わった記録を `outbox` に入れる
- 自動共有をオフにしている間は、新しい記録は `outbox` に足さない（設定は端末ごと、既定はオン）。一度送った記録（または送る予定にある記録）の直し・削除は、自動共有オフ・ログアウト中でも足す（友達の端末に古い分が残らないように。送るのはログイン中だけ）
- 送り予定と同期の位置は、ログインしたユーザーのもの。同じ端末で別の人がログインしたら、前の人の送り予定・同期の位置・送った印は消す（友達の記録は残す）

### 5.2.1 メニューを送る

- 「メニューを組んで送る」と「共有するメニューを選ぶ」で、相手がオンラインの友達なら「アプリで送る」ボタンを出す（リンクで送るボタンも残す）
- 送ったメニューは今と同じく送信履歴（`menuLog`）に入る。送れなかったら `outbox` に入れて送り直す
- 受け取った側は、今のリンクで受け取ったときと同じ処理（`mergeMenus`: 同じ名前の古い版は履歴へ、新しい名前は足す）でしまう

### 5.3 受け取る

- アプリを開いたとき、友達タブを開いたときに取ってくる（前回の時刻より新しい `updated_at` のものだけ）
- `deleted` の記録・コメントは端末からも消す
- ブロックした相手の分はしまわない
- 未読: 前回友達タブを見たあとに届いた記録と、自分の記録に付いたリアクション・コメントに印を付ける。友達タブのアイコン、友達の行、グループの行に赤い点

### 5.4 画面

- 友達タブの上: 「オンラインでつながる」
  - ログイン前: メールアドレス → 6 桁コード → 表示名
  - ログイン後: 「友達を招待」「グループを作る」、オンラインの友達とグループの一覧、つながらないときは「今はつながりません。あとで自動で送ります」
  - その下に今のリンク共有の部分（そのまま）
- 招待リンク: `#/join?c=<code>`。開くとログイン（未ログインなら）→ 友達になる／グループに入る。期限切れ・使用済みは「このリンクはもう使えません。もう一度送ってもらってください」
- グループの画面 `#/groups/:id`: 記録の一覧（新しい順）「たろう ・ 脚の日 ・ 62分 ・ 10/29 18:30」。押すと中身。各記録にリアクション（💪🔥👏）とコメント。メンバー一覧、招待リンク、グループを抜ける、名前を変える（owner だけ）
- 友達の画面: 今の画面にワークアウト時間を足し、オンラインの友達の記録にはリアクションとコメントを付けられる
- 記録・コメント・人の「…」: 「通報」「この人をブロック」
- 管理 → アカウント: 表示名の変更、自動共有のオン・オフ、ログアウト、アカウントを削除（確認あり）
- 公開ページ: `terms.html`（利用規約）を足す。`privacy.html` を書き直す（メールアドレス・表示名・共有した記録をサーバーに置くこと、消し方）。App Store の「App のプライバシー」の答えも更新する

## 6. エラー処理

| 状況 | 動き |
|---|---|
| サーバーにつながらない・一時停止中 | 記録はつけられる。友達タブに「今はつながりません。あとで自動で送ります」。前に取ってきたものは見られる |
| ログインが切れた | もう一度コードを入れてもらう。`outbox` の記録は残る |
| コードの入力ミス・期限切れ | 「コードが違うか、期限が切れています」 |
| 招待リンクが期限切れ・使用済み | 「このリンクはもう使えません。もう一度送ってもらってください」 |
| 自分の招待リンクを自分で開いた | 「自分の招待リンクです」 |
| コメントが空・200 字超え | 送れない（ボタンが押せない） |
| アカウント削除に失敗 | 「削除できませんでした。もう一度試してください」。端末の記録は消えない |

## 7. 段階

計画は 2 つに分ける。App Store に出すのは 2 が終わってから。
1. アカウント・友達・自動共有・メニューをアプリで送る（サーバーの表と決まりは全部ここで作る）
2. グループ・リアクションとコメント・通報とブロック・アカウント削除・利用規約とプライバシーの更新

## 8. テスト

- `client.ts` を偽物に差し替えて:
  - 終了で `outbox` に入り、送られる。失敗すると残り、送り直される
  - 直した・消した記録が送られる。自動共有オフなら新しい記録は送らないが、送った記録の直し・削除は送る
  - メニューをアプリで送ると相手に届き、メニュー一覧と版の履歴に入る。友達でない相手には送れない
  - 取ってきた記録が `friendWorkouts` に入り、ワークアウト時間が表示される。`deleted` は消える。ブロックした人の分は入らない
  - 未読の印が付き、友達タブを見ると消える
  - 招待（成功・期限切れ・使用済み・自分のもの）
  - グループの記録一覧・リアクション・コメント・抜ける
  - 通報・ブロック・アカウント削除
  - ログイン（コード送信・成功・失敗）
- `supabase/schema.sql` の RLS は、手順書の確認リストに沿って実際の Supabase で確かめる（2 つのアカウントで、つながっていない人の記録が取れないこと、ブロックで見えなくなること）
- 今のテストがすべて通る
