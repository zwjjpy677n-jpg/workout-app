# オンライン共有を使えるようにする（Supabase のセットアップ）

キントレ部の「オンラインでつながる」（友達と記録を自動で見せ合う・メニューをアプリで送る）は、Supabase という無料のサーバーを使います。
ここに書いた順に画面を進めれば、プログラムを書かずに設定できます。全部で 1 時間ほどです（メールの送り元の設定で、ドメインの確認待ちが長引くことがあります）。
画面の名前やボタンの位置は 2026 年時点のものです。少し違っていたら、近い名前のものを探してください。

設定しないうちは、アプリにオンラインの機能は出てきません（今までどおり端末の中だけで動きます）。

---

## 1. Supabase のアカウントを作る

1. ブラウザで https://supabase.com を開く
2. 右上の **Start your project**（または **Sign up**）を押す
3. **Continue with GitHub** を押して、いつもの GitHub アカウントでログインする
   （メールアドレスで登録してもかまいません）

## 2. プロジェクトを作る

1. ログイン後の画面で **New project** を押す
2. 次のように入れる
   - **Name**: `kintorebu`（何でもよい）
   - **Database Password**: **Generate a password** を押して出てきたものを、パスワード管理アプリなどに控えておく（あとで使うことはほぼありませんが、無くすと戻せません）
   - **Region**: **Northeast Asia (Tokyo)** を選ぶ
   - **Plan**: Free（無料）
3. **Create new project** を押す。準備に 1〜2 分かかるので、緑の表示に変わるまで待つ

## 3. 表と決まりごとを作る（schema.sql を実行する）

1. 左のメニューの **SQL Editor**（`>_` のような絵）を開く
2. **New query**（または `+`）を押して、空の入力欄を出す
3. このリポジトリの `supabase/schema.sql` を GitHub で開き、右上の **Copy raw file**（重なった四角の絵）で中身を全部コピーする
4. SQL Editor の入力欄に貼り付けて、右下の **Run** を押す
5. 下に **Success. No rows returned** と出れば成功
   - 何度実行しても壊れないように作ってあるので、失敗したら直してもう一度 Run してかまいません
   - `delete from auth.users` のところでエラーになった場合は、その旨を開発者（Claude）に伝えてください。これはアカウント削除の機能（第 2 段階で使う予定）の部分なので、オンライン共有そのものは先に進められます

## 4. ログイン用のメール（確認コード）を設定する

キントレ部は、メールに届く 6 桁の確認コードでログインします。

1. 左のメニューの **Authentication** を開く
2. **Sign In / Providers**（または **Providers**）を開き、**Email** が **Enabled**（オン）になっていることを確かめる
   - **Confirm email** はオンのままでかまいません
3. 左の **Emails**（または **Email Templates**）を開く
4. **Magic Link** のテンプレートを開き、次のように書き換えて **Save** を押す
   - **Subject（件名）**: `キントレ部の確認コード`
   - **Body（本文）**: 次の 1 行だけにする

     ```
     キントレ部の確認コード: {{ .Token }}
     ```

5. 同じように **Confirm signup** のテンプレートも、件名と本文を上と同じにして **Save** を押す
   （はじめてログインする人にはこちらのメールが届くため）

`{{ .Token }}` のところに 6 桁の数字が入って届きます。ここを書き換えないと、数字ではなくリンクが届いてしまいます。

> このままでは、友達にはコードのメールが届きません。続けて手順 5 の設定をしてください。

## 5. 友達にもコードのメールが届くようにする（メールの送り元の設定）

Supabase に最初から付いているメールの送り元は、試しに使うためのものです。2026 年時点では、**プロジェクトのメンバー（自分）のメールアドレスにしか届かず**、送れる数も 1 時間に数通ほどです。友達がログインできるように、メールを送るサービスを別に用意して、Supabase につなぎます。

> 友達を Supabase のプロジェクトのメンバーに入れれば届くようにはなりますが、**やめてください**。メンバーはデータベースの中身を全部見たり消したりできてしまいます。

やり方は 2 通りあります。自分のドメイン（`example.com` のような自分の住所）を持っている、または買ってもよいなら A、持っていないなら B を選んでください。

### A. 自分のドメインと Resend を使う（おすすめ）

Resend はメールを送るためのサービスで、無料の枠があります（2026 年時点の目安で、1 日 100 通・1 か月 3,000 通ほど。最新の枠は Resend のサイトで確かめてください）。

自分のドメインが無いと、Resend は **自分のメールアドレスあてにしか送れません**。そのためドメインが必要です。ドメインはお名前.com・Cloudflare などで、年に千数百円ほどから買えます。

1. https://resend.com を開き、**Sign up** からアカウントを作る
2. 左の **Domains** → **Add Domain** を押し、自分のドメイン（例 `example.com`）を入れて、地域は **Tokyo**（無ければ近いところ）を選ぶ
3. 画面に出てきた DNS の設定（TXT や MX などの行）を、ドメインを買ったサービスの「DNS 設定」の画面にそのまま登録する
4. Resend の画面に戻り、**Verify** を押す。数分〜数時間で **Verified** に変わるまで待つ
5. 左の **API Keys** → **Create API Key** を押す。名前は `kintorebu`、権限は **Sending access** にして作り、出てきた `re_` で始まる鍵を控える（この画面を閉じると二度と見られません）
6. 下の「Supabase に送り元を登録する」へ進み、次の値を入れる
   - **Host**: `smtp.resend.com`
   - **Port**: `465`
   - **Username**: `resend`
   - **Password**: 5 で控えた `re_` で始まる鍵
   - **Sender email**: `no-reply@自分のドメイン`（例 `no-reply@example.com`）

### B. ドメインが無いとき：Gmail から送る

キントレ部のために新しい Gmail のアカウントを 1 つ作り、そこから送るのがおすすめです（友達には、その Gmail のアドレスから届きます）。迷惑メールに入りやすいこと、1 日に送れる数に上限があること（個人の Gmail で数百通ほど）に注意してください。

1. 送り元にする Google アカウントで、**2 段階認証プロセス** をオンにする（Google アカウント → セキュリティ）
2. https://myaccount.google.com/apppasswords を開き、アプリ名に `kintorebu` と入れて **作成** を押す。出てきた 16 文字の **アプリ パスワード** を控える（いつものパスワードではなく、こちらを使います）
3. 下の「Supabase に送り元を登録する」へ進み、次の値を入れる
   - **Host**: `smtp.gmail.com`
   - **Port**: `465`
   - **Username**: その Gmail のアドレス（例 `kintorebu.app@gmail.com`）
   - **Password**: 2 で控えた 16 文字のアプリ パスワード（空白は入れない）
   - **Sender email**: Username と同じ Gmail のアドレス

### Supabase に送り元を登録する

1. Supabase の左のメニューの **Authentication** を開き、**Emails** の中の **SMTP Settings**（画面によっては **Project Settings** → **Authentication** の中）を開く
2. **Enable Custom SMTP**（または **Set up SMTP**）をオンにする
3. A または B の値を入れる。**Sender name** は `キントレ部` にする
4. **Save** を押す
5. 自分のメールアドレスと、友達（または自分の別のメールアドレス）でログインを試し、両方にコードが届くことを確かめる

> 送り元を登録したあとも、Supabase 側で 1 時間に送れる数に上限があります（**Authentication** → **Rate Limits** で見られます）。たくさんの人が一度にログインして「しばらく待ってください」と出たら、少し時間をおくか、ここの数を少し増やしてください。

## 6. 無料プランの「一時停止」について

無料のプロジェクトは、**7 日間だれも使わないと自動で一時停止** します。停止中はアプリのオンライン機能が「つながらない」状態になります（端末の中の記録は消えません）。

- Supabase から「Your project has been paused」のようなメールが届きます
- 戻すときは、Supabase にログインしてプロジェクトを開き、**Restore project**（または **Resume**）を押すだけです。数分で元どおりになり、データもそのまま残っています
- 毎週だれかが使っていれば止まりません

## 7. 接続先の URL と鍵を控える

1. 左下の歯車 **Project Settings** を開く
2. **Data API**（または **API**）を開き、**Project URL** をコピーして控える（`https://xxxx.supabase.co` の形）
3. **API Keys** を開き、**anon** **public** と書かれた鍵をコピーして控える（`eyJ` で始まる長い文字）
   - **service_role**（secret）と書かれた鍵は **絶対に使わない・どこにも貼らない** でください。こちらは何でもできてしまう鍵です
   - anon public の鍵はアプリに入れて公開される前提の鍵です。表ごとの「見てよい人」の決まり（手順 3 で作ったもの）で守られています

## 8. アプリに接続先を入れる

手順 7 の Project URL と publishable（または anon public）の鍵は、リポジトリの `.env.production` に書きます（公開してよい値です）。

```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=sb_publishable_...
```

main に入ると GitHub が自動でウェブ版を作り直します。数分後に公開中のページを開き直すと、友達タブに「オンラインでつながる」が出ます。

## 9. iPhone アプリ（Mac でビルドする版）

`.env.production` はリポジトリに入っているので、Mac ではいつもどおり `npm run build:ios` をやり直して、Xcode で ▶ を押すだけです。

## 10. ちゃんと動くかの確認リスト

スマホ 2 台（またはスマホとパソコン）と、メールアドレス 3 つを用意して確かめます。

- [ ] **A さん** でログインする（友達タブ →「オンラインでつながる」→ メールアドレス → 届いた 6 桁のコードを入れる → 表示名を決める）
- [ ] **B さん** で別の端末からログインする
- [ ] A さんが招待リンクを作って B さんに送り、B さんが開いて友達になる。お互いの友達一覧に相手の名前が出る
- [ ] A さんがワークアウトを最後まで終える → しばらくして（または B さんがアプリを開き直して）B さんの側に A さんの記録が出る
- [ ] A さんが B さんにメニューをアプリで送る → B さんの側に届く
- [ ] **C さん**（3 つ目のメールアドレス）でログインし、A さん・B さんと友達にならないままでいる → C さんには A さんの記録もメニューも見えない
- [ ] Supabase の **Table Editor** を開き、左の表（profiles, friendships, shared_workouts, menu_messages など）がすべて **RLS enabled**（鍵の絵）になっている。**RLS disabled** や **Unrestricted** と出ている表があれば、手順 3 をやり直す
- [ ] **SQL Editor** で次を Run し、`authenticated` に `SELECT` `INSERT` `UPDATE` `DELETE` が並んでいる（Supabase の初期設定のままなら並んでいます。並んでいなければ開発者に相談）

  ```
  select table_name, privilege_type
  from information_schema.role_table_grants
  where grantee = 'authenticated' and table_schema = 'public'
  order by table_name, privilege_type;
  ```

全部にチェックがついたら、オンライン共有の準備は完了です。

## 困ったとき

- **コードのメールが届かない**: 迷惑メールのフォルダを見る。自分には届くのに友達に届かないなら、手順 5 の送り元の設定ができていません（最初から付いている送り元は自分あてにしか届きません）。手順 5 の値（特に Password と Sender email）を見直す。Supabase の **Authentication** → **Logs**、Resend なら **Emails** の画面に失敗の理由が出ます。手順 4 のテンプレートが保存されているかも確かめる。1 時間に送れる数を超えていたら、しばらく待つ
- **メールにコードではなくリンクが来る**: 手順 4 の本文に `{{ .Token }}` が入っているか確かめる
- **急につながらなくなった**: 手順 6 の一時停止かもしれません。Supabase を開いて Restore を押す
- **友達タブに「オンラインでつながる」が出ない**: `.env.production` の 2 つの値が正しいか、GitHub の Actions が緑で終わったか確かめる。iPhone アプリなら手順 9
